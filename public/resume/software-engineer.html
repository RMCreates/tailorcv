How to tailor a software engineer resume to the job posting

Software engineering postings vary enormously: a backend role at a payments company and a frontend role at an agency may share a title and almost nothing else. Recruiters screen for the specific languages, frameworks and systems named in the posting, and then for evidence that you shipped working software that mattered to someone.

What recruiters and ATS filters look for

Most applicant tracking systems (ATS) match on exact technology names, so write "PostgreSQL" if the posting says PostgreSQL, not just "SQL databases". Put a compact skills section near the top, grouped by languages, frameworks, and infrastructure, and make sure every skill listed also appears in at least one bullet where you used it.

Hiring managers then look for scope and ownership: what you built, how large or critical it was, and what changed because of it. Latency, reliability, cost, developer time saved and user adoption are all good outcomes. Links to a GitHub profile or shipped product help, but only if they are current.

Keywords and skills to include (when they're true for you)

Only use the ones you can back up with real experience, and prefer the exact wording of the posting you're applying to.

  • Languages from the posting (e.g. Python, Java, TypeScript, Go)
  • REST / GraphQL APIs
  • Cloud platforms (AWS, GCP, Azure)
  • CI/CD
  • Unit and integration testing
  • Distributed systems
  • Code review
  • Docker / Kubernetes
  • System design
  • Agile / Scrum

Example bullet points

These are illustrative examples, not real candidates. Use them for structure (action, context, result) and replace the details and numbers with your own.

  • Example: Rebuilt the order-search API in Go with a read-through cache, cutting p95 latency from 900 ms to 180 ms for about 40k daily users.
  • Example: Introduced contract tests between three services and added them to the CI pipeline, which caught two breaking changes before release in the first month.
  • Example: Led the migration of a monolith's billing module to a separate service, coordinating with two teams and finishing with zero billing downtime.

Common mistakes on software engineer resumes

  • Listing every technology you have ever touched. A wall of 40 tools dilutes the ones the posting actually asks for.
  • Bullets that describe tasks ("worked on the API") rather than results.
  • Burying your most relevant project under older or less relevant jobs. Lead each role with the bullet that best matches this posting.
